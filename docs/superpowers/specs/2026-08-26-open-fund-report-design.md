# 场外基金支持 — 子项目 A：单基金分析报告 设计文档

- 日期：2026-08-26
- 状态：待实现
- 范围：子项目 A `单基金分析报告`（子项目 B/C/D 仅在文末预留接口，不在此实现）

## 背景与目标

现有系统（A 股/港股/美股/日股/韩股/台股）全部按**证券**建模：有实时价/K 线，估值 = 价格 × 数量，
分析走技术面 + 基本面，报告 Schema 的字段（MA、成交量、筹码、涨跌停、资金流、龙虎榜、板块）均为股票概念。

场外基金（公募开放式基金）**没有盘中行情，只有每日净值**，语义与证券彻底不同。因此：

1. 不把基金硬塞进证券市场；在现有证券链路之外增加一条**资产类别=fund** 的并行领域链路。
2. **骨架复用**：任务编排、LLM 分析调用、通知推送、报告历史保存、前端报告渲染、run_flow 诊断复用现有实现。
3. **领域层新增**：数据源适配、分析模型、报告 Schema、LLM Prompt 均为基金专属，不污染股票链路。
4. 股票链路零改动，避免回归。

本 spec 只覆盖**子项目 A：输入场外基金代码 → 产出单基金 LLM 分析报告**，作为后续
组合持仓估值（B）、基金提醒预警（C）、基金池巡检复盘（D）的共同底座。

## 设计

### 1. 资产识别（关键技术点）

裸 6 位代码天然歧义（例：`006229` 既可能是深市证券，也是场外基金 `中欧医疗创新股票C`）。
为不破坏现有证券语义，采用**明确后缀优先**识别：

- 支持显式后缀：`006229.OTC` 或 `006229.FUND` → 识别为 `asset_type=fund`，路由到 `analyze_open_fund()`。
- **默认不带后缀时按既有证券语义处理**（保持现有行为，不做无提示改变）。后续若需要"裸码自动纠偏"，作为可选增强，不在本 spec 承诺。
- 识别实现集中在共享市场/标的工具（参见 `src/services/stock_code_utils.py`、`src/services/stock_list_parser.py` 的 `asset_type` 机制），避免规则漂移。

### 2. 数据源（复用 akshare，零新增依赖）

已接入 akshare（`requirements.txt` `akshare>=1.12.0`），实测 `akshare 1.18.81` 可用以下接口：

- `fund_open_fund_info_em(symbol, indicator, period)` → 净值序列：
  返回列 `净值日期 / 单位净值 / 日增长率`。`indicator` 支持多种（单位净值走势、累计净值走势、资产配置、持有人结构、股票投资明细、同类排名走势等），按需选用。
- `fund_portfolio_hold_em(symbol, date)` → 基金持仓：
  返回列 `序号 / 股票代码 / 股票名称 / 占净值比例 / 持股数 / 持仓市值 / 季度`（实测 `006229` 返回 2025Q1 持仓）。

新增 `FundDataProvider`（镜像现有 `BaseFetcher` 的 fail-open / 超时 / 重试 / 降级约定），不新增 provider 实现平行逻辑，优先复用 akshare。

### 3. 数据模型

- `FundNetValueSeries`：日期 / 单位净值 / 日增长率（累计净值与回撤可由单列演进计算）。
- `FundProfile`：名称、基金类型（股票/混合/债/货币/指数/QDII/FOF）、成立日、基金经理、规模、费率（申购/赎回/管理/托管，若接口可得）。
- `FundHolding`：重仓股及占净值比例、持仓市值，以及数据来源季度。
- 数据质量元数据：`provider / as_of / data_quality / missing_fields`（遵循现有降级约定）。

### 4. 分析维度（报告内容）

1. 净值走势与区间收益率（近 1 月 / 3 月 / 1 年 / 成立来，按数据可得度）。
2. 回撤：最大回撤、当前回撤、修复时长（按净值可演进）。
3. 波动率与年化（可选，净值即可演进）。
4. 持仓集中度与前十大重仓股及其行业（跨市场，如 `006229` 持仓为港股药明系）。
5. 基金经理 / 基金规模 / 费率。
6. 同类定位（可选 v1，能力允许时）。
7. **LLM 综合解读 + 申赎建议**（基金为申赎，非买卖语义）。

### 5. 报告 Schema

- 新增基金专用字段模型（不复制股票 MA / 成交量 / 筹码 / 涨跌停字段）。
- 新增基金报告模板（结构对齐现有报告，但字段为基金语义）。
- 报告渲染（静态 HTML / 图片分享）在前端按 `asset_type=fund` 分派展示。

### 6. LLM Prompt

- 新增基金分析 Prompt 模板：聚焦净值走势、回撤、持仓、重仓股行业、经理、费率；
  **明确排除**涨跌停、北向资金、龙虎榜、融资融券、技术位等股票概念，避免套用股票语义导致幻觉。

### 7. 错误处理 / 降级

- 净值接口失败 → 降级并标注；单接口失败不阻断整条分析链路（与现有 fail-open 约定一致）。
- 某数据块缺失（如持仓）→ 在报告中显式标注缺失，不伪造。

### 8. 配置

- `.env` 新增 `FUND_SUPPORT`（默认 `false`）：关闭时基金提示/入口不展示，不影响既有证券链路。
- 同步更新 `.env.example` 与相关文档；默认"不配置也可运行，配置后增强能力"。

### 9. 前端（apps/dsa-web）

- 代码输入 / 自动补全：支持基金代码识别与提示（自动补全为可选接入，v1 至少支持手动输入显式后缀代码）。
- 报告视图：新增基金字段展示（净值曲线、回撤、重仓股表格），与证券报告按 `asset_type` 分派。

### 10. 测试

- 基金识别单测（显式后缀、裸码不误判为证券的回归）。
- 净值 / 持仓解析单测（列映射、回撤计算）。
- 路由单测：基金代码 → `analyze_open_fund`（股票链路不触发）。
- 单基金报告端到端（网络路径按 `network` 标记，或对数据源 mock）。

### 11. 边界（不承诺）

- 不承诺实时净值（净值本身为每日收盘更新）。
- 不承诺完整同类排行 / QDII 特殊结构（v1 以净值 + 持仓 + 基础资料为主）。
- 不承诺裸码"自动纠偏为基金"（需显式后缀），避免破坏证券语义。

## 为子项目 B / C / D 预留的接口（本 spec 不实现）

- **B 组合持仓估值**：Portfolio 增加 `asset_type=fund` 持仓口径，按申赎金额 / 净值估值（与股票市值口径分离）。复用 `FundNetValueSeries`。
- **C 基金提醒预警**：告警规则增加基金指标（净值涨跌幅度 / 回撤阈值 / 份额变化），复用通知链路。复用 `FundProfile` / `FundNetValueSeries`。
- **D 基金池巡检复盘**：批量拉净值 → 汇总 → 基金大盘复盘，独立于 `MARKET_REVIEW_REGION` 体系。复用 `FundDataProvider` / 分析模型。

## 风险与回滚

- **风险**：净值接口字段随 akshare 版本变化 → 解析层做列映射归一化 + 缺列时降级，避免强依赖列名。
- **风险**：裸码歧义 → 显式后缀优先，默认不改变证券语义，用户可追踪。
- **回滚**：本功能为新增独立链路 + `FUND_SUPPORT` 开关，关闭开关或回退提交即可，不触及证券链路。
