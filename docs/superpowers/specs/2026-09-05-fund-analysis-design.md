# 场外基金净值体检分析 设计文档

> 日期：2026-09-05 ｜ 状态：设计待审阅 ｜ 关联需求：让本项目支持「场外基金」分析（如中欧医疗 003095）

## 1. 背景与问题

现有系统针对(过)场内 ETF 与股票，分析引擎建立在 **OHLCV（开高低收+成交量）** 之上：K 线、均线、MACD、KDJ、量比、资金流、买卖点、止损位都依赖交易所真实价格与成交量。

用户在支付宝等处购买的**场外开放式基金**（如中欧医疗健康 003095、易方达中小盘 110011）不满足这一前提：

- 只有每日**单位净值 / 累计净值**，无盘中高低价、无成交量、无换手；
- 机制是「基金公司按每日收盘净值发份额」，涨跌只体现在净值上；
- 因而**没有** K 线量价、买卖点、支撑压力、资金流、止损位。

历史事实：项目早期用 `ef.fund.get_quote_history` 取场外基金净值，因「只有净值、无 OHLC 与成交量、喂不出技术指标」而放弃（`data_provider/efinance_fetcher.py:476`，见 Issue #541/#527）。

**结论**：不能把现有股票引擎硬套到净值上（会产出虚假的 KDJ/量价/止损信号）；必须为场外基金新增一条**净值体检**分析子路径。本文档给出该路径的设计。

## 2. 目标与非目标

### 目标
- 让场外基金代码能进入现有分析链路：加入自选 → 分析 → 生成「净值体检」报告 → 落历史库 → 推送企业微信/飞书 → Web 工作台查看。
- 报告给出**该不该拿 / 风险多大**的体检式结论，不产伪买卖点。

### 非目标（明确不做）
- 不做场外基金的 K 线画线/量价/MACD/KDJ/买卖点/止损位（净值不存在这些概念）。
- 不做货币基金/纯债基金分析（净值≈常数，无分析意义；默认降级为「不适用」）。
- 不改变现有股票 / 场内 ETF 的识别与分析逻辑（零破坏）。
- 不作为投资建议；报告显式声明「基于净值，非股票式信号」。

## 3. 数据源（东财，零配置，与 A 股同模式）

新增 `data_provider/fund_fetcher.py`，复用已验证可达的东财（东方财富）接口：

| 数据 | 端点 | 取回字段 |
|------|------|---------|
| 每日净值序列 | `api.fund.eastmoney.com/f10/lsjz?fundCode=<code>&pageIndex=1&pageSize=<n>` | 日期 `FSRQ`、单位净值 `DWJZ`、累计净值 `LJJZ`、日涨跌% `JZZZL`、基金类型 `FundType` |
| 名称/基础信息 | `fund.eastmoney.com/pingzhongdata/<code>.js` | `fS_name`、`fS_code`、净值走势 `Data_netWorthTrend` 等 |
| 底层重仓股 | `api.fund.eastmoney.com/f10/JJCC?fundCode=<code>`（东财基金持仓，候选端点） | 重仓股代码/名称/占比 |

注：`pingzhongdata` 通常含净值走势与底层数据。重仓股候选端点为东财 `f10/JJCC`,实现时以真实返回为准,若不可用则该区块 fail-open 降级为空并标注。已实测 `lsjz` 与 `pingzhongdata` 在 003095 上返回真实数据。

设计要点：
- **免费、无 key**，失败降级与 A 股免费源一致（fail-open，不拖垮主流程）。
- 默认**近 N 个交易日**（如 250 个）净值，用于收益/回撤/波动/Sharpe 计算；不足时按可得长度降级并在报告标注。
- 数据源不支持实时估算净值（盘中估算接口当前不可达）；**体检报告只用每日净值即可**，不依赖盘中估算。

## 4. 代码识别与路由（关键，避免误伤股票）

场外基金 6 位码（`003095`）与 A 股（`003816`）**存在前缀重叠**，不能靠规则/算法猜测，否则会把 A 股误判成基金。方案：**显式标记**。

- **标记形式**：自选/参数中基金代码统一带 `fund:` 前缀，如 `fund:003095`；同时保留 `STOCK_LIST` 原样用于股票。新增独立配置入口（`FUND_LIST`）与 CLI/API 参数，二者互不混淆。
- **解析**：`fund:` 前缀 → `fund` 标的类型；否则走既有股票/ETF 判断。`get_market_for_stock` / 市场识别**不改**，仅在其上游按标记分流。
- **导入/补全（Web）**：基金走「基金搜索」补全；为避免歧义，用户输入的裸 6 位码默认按股票处理（现状），要分析基金必须带 `fund:` 前缀（安全侧默认），并在 UI 提示。

## 5. 分析引擎与报告结构（净值体检）

新增 `src/services/fund_analysis.py` + 基金专用 prompt（与股票 prompt 隔离）。

### 指标层（确定性计算，不用 LLM）
- 近 1 月 / 3 月 / 6 月 / 1 年(可得) **收益率**
- **最大回撤**（高峰到低谷）
- **年化波动率**
- **Sharpe**（年化收益 − 无风险利率）/ 年化波动；无风险利率取配置项 `FUND_RISK_FREE_RATE`（`.env.example` 同步，默认 0.02），缺失时报告标注
- **累计净值趋势**分类（上行 / 高位回落 / 震荡 / 下行）——基于净值曲线拟合，非 K 线均线
- 净值曲线最近一段波动描述
- **底层重仓股**列表（榜单一览，供 LLM 与「重仓股区块」消费）

### LLM 结论层（基金版 prompt 生成）
- **风险等级**（低/中/高）
- **持有/关注/风险提示**判断（是否建议继续持有、需关注的回撤/波动风险）
- **重仓股解读**（若重仓股相关）与**持仓集中度/风格**概述
- **重要信息速览**（重仓股新闻/舆情，复用搜索服务，可降级）
- **一句话结论**：如「回撤超过 X%、高波动，风险偏高，建议关注企稳 / 可继续持有」

**明确条款**：
- 报告**无**买卖点、无止损位、无仓位建议、无「买入」档位——因净值无此概念；报告头部显式声明。
- 报告类型新增 `fund`，与 `stock` 类型区分存储与渲染（历史库 + Web 报告卡片 + 通知模板）。

## 6. 链路整合（像股票一样）

在现有流程入口接入，复用既有基础设施：

- **自选/调度**：`FUND_LIST`（或 `fund:` 标记代码）进入每日分析；failing 基金 fail-open，不中断当天股票分析。
- **单股流程**：`src/core/pipeline.py` 按标的类型分流——`fund` 走 `fund_analysis`；`stock/etf` 走现有引擎。
- **报告生成/推送**：`src/notification.py` 的 `generate_aggregate_report(results, report_type)` 增加 `fund` 分支；基金报告套基金模板。推送链路（企业微信/飞书/邮件）复用，仅换模板与文案声明。
- **历史库**：新增 fund 报告类型；`/api/v1/history` 与 Web 工作台能查询/渲染基金报告。
- **飞书云文档**：`src/feishu_doc.py` 聚合时纳入基金报告段落（与个股大盘复盘并列）。

## 7. 边界与风险

| 项目 | 处理 |
|------|------|
| 货币基金/纯债基金（净值≈常数） | 默认**排除**，报告降级「不适用」并提示原因 |
| 报告无买卖点 | UI 与推送文案显式声明「基于净值，非股票式信号，不构成投资建议」 |
| 免费源稳定性 | 与 A 股免费源一致，接口变动时 fail-open；不中断主流程 |
| 代码歧义 | 仅 `fund:` 标记识别，裸码默认股票；不猜、不改现有识别 |
| SHARPE/指标数据不足 | 按可得长度降级，报告标注数据范围与缺失项 |

  - 真实取值路径抽检（联网可观测）：003095 名称/净值解析、510300（ETF）仍走股票路径。
- `python -m py_compile` 变更 Python 文件。
- `./scripts/ci_gate.sh`。
- 交付说明覆盖：改了什么、为何、验证、未验证项、风险、回滚（移除 `fund:` 标记与 fund 分支，A 股路径不受影响）。

## 9. 回滚方式

移除 `fund:` 标记识别、`data_provider/fund_fetcher.py`、`src/services/fund_analysis.py`、`fund` 报告类型分支（notify/history/web/feishu）与对应文档声明；现有股票/ETF 识别与分析逻辑不改，回滚后 A 股链路保持原样。
